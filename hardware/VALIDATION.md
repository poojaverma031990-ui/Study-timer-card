## Required engineering work

1. Open and review the schematic in KiCad 7. This is a generated draft. Check
   inherited symbol geometry and every pin/net. Unused GPIOs are marked NC.
   Review duplicate stacked power pins, add appropriate power flags, and run ERC.
2. Confirm the selected RP2040 package and exposed-pad connection, flash package,
   USB connector footprint, crystal load/drive requirements, AMS1117 stability
   and thermal behavior, capacitor voltage ratings, buzzer current, and transistor
   pinout. Add USB ESD protection and assess input protection/inrush needs.
3. Check USB bus current budget and enumeration behavior; do not assume 500 mA
   is available before enumeration. Use only a 3.3 V-compatible OLED with the
   documented pin order. Check that I2C pullups are not excessively paralleled.
4. Replace every REVIEW_ENVELOPE with a verified electrical footprint and update
   from schematic. These envelopes are placement hints ONLY, not land patterns.
   Avoid OLED mechanical overlap. Add courtyards, test points, and keepouts.
5. Route power at 0.5 mm, signals at 0.25 mm as a starting rule; USB differential
   routing must instead be calculated for the chosen stackup and 90 ohm target.
   Keep flash and crystal wiring short. Specify 0.8/0.4 mm vias, add GND zones on
   both layers, stitch grounds, refill, and run DRC and schematic parity checks.
6. Build CircuitPython for the exact selected flash/board, then bench-test USB
   boot, flash programming, supply rails, current, I2C, LED polarity, PWM buzzer,
   reset/BOOTSEL, and timer accuracy. Firmware defaults to OLED address 0x3C.
7. Choose verified supplier parts with package matches and current Basic status.
   Resolve any non-Basic parts honestly. Quote boards, assembly, OLED, shipping,
   and taxes before claiming any budget total.
8. After clean ERC/DRC and prototype validation, export copper, mask, silk,
   paste, outline Gerbers and plated/non-plated drills at a chosen auxiliary
   origin (0,0). Include a README/TXT manifest and inspect every file in a
   separate Gerber viewer. File size is not evidence of correctness; never pad
   an archive just to exceed 50 KB. Generate centroid data for assembly too.

`schematic.pdf` is a connection-review document generated by ReportLab, NOT a
KiCad graphical schematic export. `pcb.png` is a labeled placement illustration,
NOT a render of a finished PCB. A zero-unconnected report from this padless
placement file would be meaningless and must not be presented as a pass.
